# Playbook：review（代码审查）

## 触发条件

用户要求审查分支、差异、Pull Request 或近期实现的变更。

## 前置条件

- 固定比较基线（提交、分支、合并基点或工作区差异）已知或可发现。
- 未明确授权修复时，默认权限为 `READ`。

## 顺序步骤

1. 进入 `dw-review`，固定准确的差异范围（`git diff`、基线 SHA 或变更文件列表）。
2. 分两个维度检查：`Spec`（需求和验收是否满足）与 `Standards`（仓库约定、安全、可靠性和测试）。
3. 在安全且只读的前提下重跑相关检查，或直接核对引用的命令证据。
4. 输出按严重度分类的问题（`critical`、`major`、`minor`、`info`），包含 `file:line`、机制及验证状态。

## 证据

- 审查的提交或差异范围、执行过的验证命令，以及每项问题的具体 `file:line` 引用。

## 失败与停止条件

- 提交报告后即停止；除非明确授权，不得编辑、提交或推送。
- 未验证的运行时假设应标记 `unverified`，不得作为已证实缺陷。
