# Playbook：feature（功能开发）

## 触发条件

用户请求新增功能、接口或行为。

## 前置条件

- 已取得 `LOCAL_EDIT` 授权；或者请求尚处于等待批准的 `dw-design`/`dw-plan` 阶段。

## 顺序步骤

1. 需求模糊，或涉及架构/公共 API 变更（`standard`/`rigorous`）时，执行 `dw-design` 并在关键决策上取得用户批准。
2. 多步骤或跨模块任务执行 `dw-plan`，生成 `spec.md` 和无环垂直任务切片；`quick` 模式只需几行内联计划。
3. 使用 `dw-build` 逐切片实现，先检查脏工作区；只有存在子 Agent 且文件互不重叠时才考虑并行。
4. 在最后一次编辑后执行真实测试或构建命令。
5. 依据模式和风险执行适度的 `dw-review`。

## 证据

- 需要时的设计批准记录、变更文件路径、验收标准映射，以及确切验证命令与退出码。

## 失败与停止条件

- 未获批准的高影响设计变更不得开始实现。
- `dw-build` 或 `dw-review` 完成后，不得自动调用 `dw-ship`。
