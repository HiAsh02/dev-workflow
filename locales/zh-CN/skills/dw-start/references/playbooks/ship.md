# Playbook：ship（交付与发布）

## 触发条件

用户要求本地提交、推送分支、创建 Pull Request、合并、打标签、发布或部署。

## 前置条件

- 用户明确授权相应操作级别（`LOCAL_COMMIT`、`REMOTE_WRITE` 或 `DESTRUCTIVE`）。
- 已核实目标仓库、远端和分支。

## 顺序步骤

1. 进入 `dw-ship`，将操作拆分为独立权限检查（`commit`、`push`、`pr`、`merge`、`release`、`deploy`、`delete`）。
2. 核实前置条件：预期的 `git status`、HEAD SHA、远端与分支，以及最终编辑后的最新通过检查。
3. 拒绝未授权的级别；授权或目标不明确时停止并提供交付前清单。
4. 只执行明确批准的操作。
5. 执行后核验实际远端状态（提交 SHA、PR URL、标签或 API 状态）。

## 证据

- 交付前检查结果、确切执行命令、本地或远端 SHA/URL，以及回滚说明。

## 失败与停止条件

- 目标分支或仓库与授权不符、检查失败，或脏文件可能被意外包含时立即停止。
- 不得根据通过的代码审查或历史会话推断推送、合并或发布权限。
