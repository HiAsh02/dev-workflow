# dw-debug

## 目的

在修改代码之前通过可复现证据找出真正的故障根因，并确保获授权的修复包含回归保护。

## 适用场景

- 测试失败、API/CLI 抛出意外错误，或先前正常的行为发生回归。
- 根因未知，或此前的补丁未能解决问题。

## 不适用场景

- 明确规格的新功能开发，应使用 `dw-design`、`dw-plan` 或 `dw-build`。
- 尚未确认故障机制就盲目猜测并实施未经验证的补丁。

## 输入

- 故障现象、错误消息、堆栈跟踪或日志。
- 复现提示、环境上下文，以及回归问题中最后一个已知正常的提交或版本。
- 明确的授权级别：仅 `READ` 诊断，或已授权 `LOCAL_EDIT` 修复。

## 能力要求

- 可通过文件检查、日志分析及只读复现命令完成诊断。
- 在 Git/Worktree 可用时，可通过 `git diff` 或隔离 Worktree 中的 `git bisect` 定位回归；否则手工查看差异并执行针对性检查。

## 执行步骤

1. **只读预检查**：检查 `git status` 并保护已有未提交改动；诊断期间不修改源码。
2. **确定性复现**：运行能够触发问题的最小安全命令或跟踪。如果无法复现，应收集确切的环境缺失条件后停止，不得猜测。
3. **缩小故障范围**：
   - 存在已知正常 SHA/版本时，先检查 `git diff <good>..HEAD`；仅在安全且得到授权时于隔离工作区执行 `git bisect`。
   - 跟踪失败的数据和控制流，定位违反不变量的具体 `file:line`。
4. **验证可证伪假设**：解释观察到的状态为何会导致故障，并通过代码或日志验证后再提出或实施修改。
5. **检查编辑授权**：
   - 只要求 `READ` 诊断时，报告根因、证据和建议的最小修复，不修改文件。
   - 获得 `LOCAL_EDIT` 授权后，实施最小根因修复（不是用 catch/retry 掩盖症状），增加能够证明修复前失败、修复后通过的回归测试，并重跑受影响检查。
6. **熔断规则**：连续两次修复尝试均未解决问题时，停止编辑；在不触碰用户 WIP 的前提下安全隔离或撤回失败实验，重新检查假设。

## 输出

- 复现步骤或命令与观察到的失败输出；如无法复现，明确解释原因。
- 已确认的根因（`file:line` 及机制）。
- 获授权修复时：最小差异、增加或更新的回归测试，以及修复后通过的命令输出和退出码。

## 失败处理与降级策略

- 运行环境缺少复现必需的依赖、凭据或测试执行器时，报告 `BLOCKED` 和确切缺失项，不得声称已经验证根因。

## 授权

- 默认是**只读（READ-ONLY）**诊断。
- 应用修复必须有明确 `LOCAL_EDIT` 授权，例如用户要求“修复这个缺陷”。
- 修复缺陷不自动授予 `LOCAL_COMMIT`、`git push`、PR 创建或部署权限（参见 `dw-ship`）。

## 验证

- 确认根因解释能够涵盖所有观察到的症状。
- 对已实施的修复，必须在最终编辑之后运行回归测试和受影响测试集，并确认退出码 `0`。
